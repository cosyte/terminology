## What is compared

The recorded responses declare their own tolerance and the runner honours it: `$optional-properties$` (elements that need not be present), `$optional$` (one element that need not be present), the `$id$` / `$uuid$` / `$instant$` placeholders for values that legitimately vary per run, and the `response:flat` variant a fixture supplies for a server that does not build a hierarchical expansion.

Beyond that vocabulary the runner applies the tolerances below. Every one exists because the suite records a server's HTTP response while this package is a library whose answer is narrower by construction. They are named here because a tolerance nobody can see is indistinguishable from a pass that was not earned.

- **expansion-projection**: For expand, only the recorded expansion.contains membership is compared. The rest of the recorded ValueSet resource (id, url, version, name, title, status, date, publisher, compose, and expansion's identifier, timestamp, total, offset, parameter and property) is not, because expand returns a membership result rather than a ValueSet resource.
- **member-projection**: A member is compared on system, code and display only. abstract, inactive, designation, property, extension and nested contains are not compared, because ExpandResult.contains is a list of Coding.
- **unordered-membership**: Membership is compared as a set keyed by system and code, not as an ordered sequence. FHIR does not define expansion order and the engine documents first-seen order, so an order difference is not an answer difference.
- **result-only**: For validate-code, only the recorded result parameter is compared. message, display, code, system, version, issues and codeableConcept are not, because validateCodeInValueSet answers membership and nothing else.

- `unsupported-request-parameter`
