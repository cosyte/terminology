The publish gate's argument guard refused a fixed list of blinding spellings, and `-fjson` was not on it: a value fused to a short flag hid the one sentence the gate reads, and it handed back a pass over a tarball carrying no types.

Development tooling only: `scripts/attw.mjs` ships in no tarball, and this package's public surface, build output and runtime behaviour are unchanged.

**The rules of the gate are stated once, in `scripts/attw.mjs`'s docblock, and this entry is a pointer rather than a second copy.** The previous shape of this guard was described in several committed files at once and the copies disagreed — this repo's `CLAUDE.md` claimed a refusal "by option name, wholesale" that a fused short option walked past, and called `--config-path` refused "by inference, not measurement" when the real-file half takes one command to measure. That paragraph is now a pointer too.

**The remedy is an allow-list, which is why no spelling is enumerated.** The gate forwards `--profile` and `--no-definitely-typed` and refuses every other argument, including ones that blind nothing. "Harmless" is a judgement a script cannot make from an option name, and being over-strict about an argument nobody passes to a repo's own publish gate costs less than a route back to a false green. Widening the set is a deliberate one-line edit.

**Measured on this repo's pinned `@arethetypeswrong/cli@0.18.4`, on a fixture whose tarball carries no types.** Each of `-fjson`, `-Pf json` and `-Pfjson` exited 0 with the untyped sentence absent and a non-empty transcript, so the empty-output net could not backstop them; `--help`, `-h`, `--version` and `-V` did the same, and neither half of the design could tell any of them from a pass. `--config-path` naming a real file that sets `format` blinded the same way — while the nonexistent path the old test named blinds **nothing**, since `readConfig()` swallows the `ENOENT` and the sentence is still printed. That test asserted a refusal over a case that could not have hurt the gate; both halves are pinned now.

**Two promises the preflight walked past, each measured to leave bare `attw` at exit 0.** It never read `bin`, so a manifest could promise a command that is not in the tarball and the gate would say nothing — `attw` analyses types and does not look at `bin` at all. And it skipped a path written without a leading `./`, which is legal and is the spelling npm's own documentation uses, so `"main": "dist/index.js"` was dropped silently while the gate still reported it had checked. This package declares no `bin`; that half is here because every sibling copies this file, and it is pinned on a fixture that does declare one.

**A false explanation of a correct red is deleted rather than reworded.** The preflight used to end by naming the exit code `attw` "would have" produced. It reads the manifest and never the tarball, and the tarball is what decides: `analysis.types` is `containsTypes()` in `@arethetypeswrong/core`, which is `listFiles(directory).some(ts.hasTSFileExtension)` — any TypeScript-extension file in the packed tarball, computed before an entrypoint is resolved. A package whose `files` packs a whole `dist/` can lose every declared declaration and still hand `attw` an undeclared chunk declaration to find, at which point it exits 1 and the sentence is false. The failure now says what it checked and that it cannot speak for `attw`.

**A limit found while grading this, filed rather than closed.** The `.attw.json` refusal names `quiet` and `format`, but `readConfig()` sets an option value for **every** key except `configPath`, `help` and `version` — so a committed config reaches options this gate does not name, `definitelyTyped` pointed at a `.tgz` among them, which merges those types in and can make an untyped tarball analyse as typed. It predates this change, and the allow-list closes only its argv half — `--definitely-typed` on argv is now refused, where the deny-list forwarded it — while the config route is untouched. It is written down instead of answered: adding a key would rebuild, on the config side, the deny-list this change just retired on the argument side, and refusing a `.attw.json` outright is a behaviour change for callers who legitimately have one.

**What this does not do.** It does not touch `scripts/verify.sh`, `scripts/phi-scan.ts` or anything under `src/`. It does not close the residual above by reading the tarball — that is a second moving part for a wrong _explanation_ of a correct red, and the instruction on record is to weaken the claiming sentence, which is what deleting it does. It does not carry the fix to the siblings or to the parser template that mints new repos; each is its own repo's change. And the `tsup` window that supplies the race is described as seconds rather than a figure: independent measurement sets across this ecosystem disagreed, and only the order of magnitude is stable.
