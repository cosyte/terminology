"@cosyte/terminology": patch
---

ValueSet binding: four membership and display answers now agree with the HL7 terminology-ecosystem responses they used to contradict. Every one of them was answered with confidence before (a decided `result`, or an expansion marked `complete: true`), so a consumer had nothing to branch on.

`ValueSet.compose.inactive` is read and honoured. It was dropped at load, so a value set declaring `inactive: false` expanded to include a code the supplied release marks retired. `ValueSetCompose.inactive` now carries the declaration, and a declared `false` screens every `include` branch alike: enumerated, filtered and whole-system. A code the release marks not active is omitted; a concept the release carries no status for is KEPT, because absence of status is not evidence of inactivity; and a component whose activity no supplied release can decide contributes nothing, marks the result `complete: false` and surfaces a value-free `TERM_VALUESET_CANNOT_EXPAND` diagnostic at the component's index path, so `contains` stays a true lower bound rather than a set that may hold inactive codes. `validateCodeInValueSet` mirrors the same rule, so membership and expansion never disagree: a not-active code is a decided non-member, and an activity that cannot be checked is the typed `undetermined`, never a decided answer. An `exclude` is not screened, since screening it would leave an excluded code a member. An absent or `true` `inactive` omits no code on activity grounds, and a pre-computed `expansion` still passes through untouched. `loadValueSet` throws the typed `TERM_VALUESET_MALFORMED` for an `inactive` that is present and not a boolean, naming the value-free path, rather than dropping it silently. The value set's own declaration is what is read: `$expand`'s `activeOnly` request parameter is not modelled.

An enumerated member now takes its display from the supplied release when the value set supplies none. The value set's own `display` still wins and is still carried verbatim, even where the release names the code differently. Nothing is invented: with no release supplied for the component's system, no such code in it, or no display on that code, the member comes back with no display at all, and the expansion's completeness and diagnostics are unchanged either way, because a missing display is not a missing member. No display is taken from a release whose version disagrees with the component's declared pin. This closes an inconsistency between three branches of one operation: the filter and whole-system branches already built every member with the release's display.

A `property` filter now reads every value a concept carries for the property. `CodeSystem.concept.property` is `0..*`, and only the first match was read, so a concept carrying `dup = alpha` and `dup = beta` was not selected by `dup = beta` and a valid member read as a non-member with `complete: true`. `=` and `in` now match on ANY of the concept's values, `not-in` only where NONE of them is in the filter's set, and `exists` follows whether the concept carries any at all. A concept carrying no value for the property is unchanged (`=` and `in` miss, `not-in` matches), and a non-string property value still compares by its stringified form.

A `Coding` that carries no `system` is no longer decided a member of a system-scoped component. A component naming a `system` selects only codes drawn from it, so an unqualified coding names none of them: the component is a definite non-match, and a value set whose components all name a system decides `result: false` rather than asserting the code into it on the strength of its code string alone. This removes a fabricated `true`; it turns no refusal into an answer. A component the engine could not evaluate (no release supplied, an unsupported operator, a declared version the supplied release disagrees with) still returns the typed `undetermined` exactly as before, and a coding whose `system` matches the component's is answered exactly as before.

`ValueSetCompose.inactive` is added. No exported member was removed or renamed.
